# DECISIONS

Calls made without asking, with the reason. Newest last.

**D1. No Agent Relay workers; the lead built all four lanes.** The build workspace had no `codex` binary and no `OPENAI_API_KEY`, and lanes B and C are Codex lanes. Lane prompts are saved in `lanes/A.md`…`lanes/D.md` with owned paths and gate commands so they can be run in four terminals.

**D2. Netlist comes from the `.kicad_pcb`, not the repo's `Easyduino_RP2040.xml`.** `kicad-cli` is not installed in the build environment. The repo ships an Eeschema 7.0 export (`Easyduino_RP2040.xml`, 2023), but the current `.kicad_pcb` is a later revision. It has real test points TP1–TP14, LEDs D3/D4, RUN button SW2, `/GPIO0`-style net names, R9 moved to XOUT, and R8/R10/R11 marked DNP. Using the stale netlist with the new PCB drew the wrong board and modeled the wrong circuit. `core/triage/pcb_netlist.py` reads every pad's net and pin function plus the footprint DNP flags from the PCB and writes a kicadxml-style `boards/<id>/netlist.xml`. When `kicad-cli` exists, `make board` uses `kicad-cli sch export netlist --format kicadxml` instead. The source repo is pinned to commit `53b14b66` (`EASYDUINO_REV` in the Makefile).

**D3. DNP parts are drawn but not electrical.** `R8`, `R10` and `R11` are DNP in the PCB. They are excluded from resistor paths, test-point placement and fault targets.

**D4. Test points prefer real `TP*` pads.** For each net with ≥2 nodes there is one probe point `TP_<net>`, placed on the most probe-friendly pad: a real TP pad first, then 0402 passives, connectors, small parts and the fine-pitch IC last. `SUPPLY` (bench supply current) and `USB_HOST` (host enumeration log) are pseudo test points.

**D5. Fixture = behavioral model, not SPICE.** It models a power tree with Schottky drop and LDO dropout, a 150 mA current-limited supply, unpowered DMM R-to-GND (golden rail values from `roles.yaml`, a 600 kΩ ESD path per IC pin, resistors one hop away), a crystal, the RP2040 boot chain (XIP app / USB boot ROM / hang without XOSC), UART banner, LED and USB. It adds seeded ~1% Gaussian noise (5 ppm on frequency). The golden-board `nominal` in `board.json` is produced by the same model with no fault.

**D6. Vocabulary additions to the contract.** `usb_enum` adds `enum_error` (attach seen, enumeration failed). Without it a USB D− open, a wrong USB series resistor and a D+/D− bridge cannot be told apart from "nothing attached". `logic` adds `toggling_dim`, which records what a technician sees at S7 when the LED blinks dimly. `Nominal.r_gnd` (golden reading) and `Component.dnp` were added.

**D7. Scoring guards.** Hypotheses are capped at 3 nets and 3 refdes, so a method cannot list every net to buy overlap hits. GND is excluded from truth and predictions. PIN_BRIDGE truth nets are the two bridged nets (minus GND). RAIL_OPEN truth nets are the regulator's input and output.

**D8. Fault picking is stratified, never hard-coded.** Candidates come from roles and topology: decoupling caps per rail, power-tree edges, USB series R / LED series R / crystal load caps, crystals, adjacent pins (n, n+1) on the same QFN side (exposed pad and corners excluded), and IC pins on qspi/usb/clock nets. SIGNAL_OPEN on gpio is limited to the nets the S7 smoke test exercises (UART TX, LED GPIO), because an open on an unexercised header GPIO has no panel signature at all. PIN_BRIDGE has no such filter, so bridges on unexercised GPIOs can occur; those are deliberately hard. Buckets are round-robin and repeat only when exhausted. The 30 cases are shuffled before ids are assigned.

**D9. Leak test.** Class names and all net names necessarily appear in the agent prompt: the instructions list the classes and the board lists every net. The leak test therefore checks four things. The case_id and the serialized truth target never appear. Truth keys (`"cls"`, `"target"`, `"params"`, `"seed"`) never appear. The class name never appears in the user message. The whole prompt except the panel values is byte-identical across all 30 cases. The last check is the strong one: nothing case-specific can leak outside measured values.

**D10. Agent cache can be replayed without a key.** Cache key = sha256(case_id | agent | model | PROMPT_VERSION | prompt-file hash). If every case is cached, `make bench` replays the agent results with no key and no network. With a partial cache and no key, the agent is skipped entirely, so methods are always compared on identical case sets.

**D11. Durable Actors API as verified.** The npm package (0.14.6) ships no `docs/`. The reference guide was read from the GitHub repo (TerseAI/durable-actors `docs/reference/typescript-guide.md`) and everything was verified against a running `durable-actors dev`. Findings: helper methods must be JS-private (`#name`) because every prototype method must be async; socket message types `state`/`state_update` are reserved, so the actors send `session` and `bench`; `prepareWebsocket` needs `metadata: null`. The generated client is committed under `gateway/generated/` so the gateway typechecks without a running actor server.

**D12. Rules baseline and fixture share an author.** Both were written by the lead in the same session, so the rules encode exactly the signatures the fixture produces. This makes the rules baseline near-ceiling on this benchmark. It is reported as a limitation, not hidden.

**D13. Probe budget is locked.** The Agents SDK runs sync function tools via `asyncio.to_thread`, so several `probe` calls issued in one model turn run concurrently. Without a lock each one passed the `remaining <= 0` check before any appended, and a 10-thread test recorded 10 probes against a budget of 4. `ProbeSession.probe()` now holds a `threading.Lock` across check, measure and append. `test_probe_budget_holds_under_threads` and `test_agent_runs_end_to_end` (6 parallel probes in one turn → exactly 4 recorded, 2 budget errors returned to the model) cover it.

**D14. The agent path is tested end to end without a key.** `core/tests/test_agent_e2e.py` swaps in a scripted `agents.Model` via `agent.MODEL_OVERRIDE` (tests only). Everything else is the real SDK: `Agent`, `Runner.run_sync`, `function_tool`, strict structured output, usage accounting, the cache and `bench.run_case`. It also checks the bytes the model actually received for leaks, and that the cache replays with no key. SDK symbols were verified against the installed `openai-agents==0.24.0` (`openai` 3.42.0).

**D15. Errored cases are counted and spend without prices is flagged.** A crashed method still scores as a miss, but `summarize()` now reports `errors`, the bench logs a warning and `report.md` prints "N/30 cases errored". A rate-limited run therefore cannot pass as a weak agent. Errored cases are not cached, so a rerun retries only those. If `PRICE_IN_PER_M`/`PRICE_OUT_PER_M` are blank, `MAX_USD` cannot be enforced; the bench now says so before a live agent run instead of silently not capping.
